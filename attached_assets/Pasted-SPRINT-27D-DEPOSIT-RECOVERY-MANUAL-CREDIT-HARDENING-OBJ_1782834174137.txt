SPRINT 27D — DEPOSIT RECOVERY & MANUAL CREDIT HARDENING

OBJECTIVE

Complete the administrative recovery workflow for deposit verification.

This sprint focuses ONLY on recovery operations.

Do NOT modify:

- Deposit verification engine
- Blockchain adapter
- Worker
- Wallet credit implementation
- Financial calculations
- Investment engine
- Income engines

Reuse existing production code wherever possible.

==========================================================
PART 1 — UNIVERSAL RE-VALIDATE
==========================================================

Expand the Re-Validate functionality.

The button must be available for every verification that has NOT successfully completed.

Supported statuses:

FAILED
EXPIRED
VERIFICATION_DELAYED

(and any future retryable status)

It must NOT appear for:

COMPLETED
CREDITED
REJECTED

Behaviour:

• verificationStatus → VERIFYING
• nextCheckAt = now
• Preserve txHash
• Preserve timeline
• Preserve verificationAttempts
• Preserve audit history

The worker must process the SAME verification record.

Never create a duplicate verification.

PART 5 — CREDIT AMOUNT
==========================================================

Allow the administrator to enter the amount actually received.

Rules:

positive decimal only

greater than zero

maximum 8 decimal places

Display:

Blockchain Amount

Admin Credit Amount

If the values differ

show a prominent warning.

Example:

Blockchain Amount

100.00000000

Admin Credit Amount

98.50000000

⚠ The credited amount differs from the blockchain amount.

Require explicit acknowledgement.
