Sprint 25A and Sprint 25A.1 are now complete and production-hardened.

Sprint 25B has ONLY ONE responsibility:

Replace the Mock Blockchain Adapter with a production-ready Binance Smart Chain (BEP20) Blockchain Adapter.

It is NOT a financial engine sprint.

# Multiple RPC Endpoints

Support multiple RPC providers.

Configuration:

BSC_RPC_PRIMARY=

BSC_RPC_SECONDARY=

BSC_RPC_TERTIARY=

If one provider fails:

Automatically retry the next provider.

The Deposit Verification Engine must not know which provider is being used.

Everything configurable through environment variables.

Examples:

BSC_RPC_PRIMARY

USDT_CONTRACT_ADDRESS

CHAIN_ID

REQUIRED_CONFIRMATIONS

RPC_TIMEOUT_MS

RPC_MAX_RETRIES

MAX_RPC_CONCURRENCY

Never hardcode production values.

# Verification Result

The adapter should expose one unified verification result object.

Example:

* found
* successful
* confirmations
* requiredConfirmations
* senderAddress
* recipientAddress
* tokenContract
* tokenSymbol
* amount
* decimals
* network
* blockNumber
* transactionHash
* timestamp

The Deposit Verification Engine consumes this object.

The adapter never changes deposit states.

The adapter never writes to the database.

---

# Verification Rules

The adapter must verify:

✓ Transaction exists

✓ Transaction successful

✓ Correct blockchain (BSC)

✓ Correct Chain ID

✓ Recipient matches Prime Wave wallet

✓ Token contract matches official USDT BEP20 contract

✓ Amount greater than zero

✓ Confirmation count

Return verification results only.

Never approve deposits directly.

---

# RPC Resilience

Implement:

Primary RPC

↓

Retry

↓

Secondary RPC

↓

Retry

↓

Tertiary RPC

↓

Fail gracefully

Do not expose RPC failures to the user.

Return meaningful adapter errors.

---

# Security

Reject:

* Unknown transaction
* Failed transaction
* Wrong chain
* Wrong recipient
* Wrong token contract
* Zero amount
* Unsupported token
* Unsupported network

Never trust user input.

All values must come directly from the blockchain.

---

# Logging

Log:

* RPC Provider used
* Verification duration
* Confirmation count
* Retry count
* Failover events

Do NOT log private information.

Do NOT log secrets.

---

# Performance

Support configurable RPC concurrency.

Reuse existing worker concurrency settings.

Avoid duplicate blockchain requests wherever possible.
