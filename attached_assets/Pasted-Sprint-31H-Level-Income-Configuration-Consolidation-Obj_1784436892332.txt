Sprint 31H — Level Income Configuration Consolidation

Objective

PrimeWave has two conflicting sources of truth for Level Income percentages.

Current state:

1. Backend payout engine:
   level-income.service.ts

   LEVEL_RULES = {
     1: 1,
     2: 1,
     3: 1,
     4: 1,
     5: 1
   }

2. Database:
   system_settings.level.config

   Currently contains:
   5%
   3%
   2%
   1.5%
   1%

The official PrimeWave business rule is:

Level 1 = 1%
Level 2 = 1%
Level 3 = 1%
Level 4 = 1%
Level 5 = 1%

The backend is already paying correctly.

The database configuration is incorrect and must be aligned.

====================================================
IMPORTANT
====================================================

DO NOT change the business logic.

DO NOT change payout behaviour.

DO NOT change historical ledger records.

DO NOT compensate any users.

The objective is only to eliminate duplicate configuration and make the configuration consistent.

====================================================
PART 1 — Make system_settings the Single Source of Truth
====================================================

Remove the hardcoded LEVEL_RULES constant.

Replace it with a configuration loader.

Load:

system_settings.key = "level.config"

Expected structure:

[
  { "level": 1, "rate": 1 },
  { "level": 2, "rate": 1 },
  { "level": 3, "rate": 1 },
  { "level": 4, "rate": 1 },
  { "level": 5, "rate": 1 }
]

Use this configuration during every level income calculation.

No hardcoded percentages should remain.

====================================================
PART 2 — Correct Production Configuration
====================================================

Update the current level.config value to match the official business rules:

Level 1 → 1%

Level 2 → 1%

Level 3 → 1%

Level 4 → 1%

Level 5 → 1%

This is a configuration correction only.

====================================================
PART 3 — Validation
====================================================

When loading level.config:

Validate:

✓ Exactly five levels exist.

✓ Levels are numbered 1–5.

✓ Every rate is numeric.

✓ Every rate is >= 0.

If validation fails:

Fail startup with a clear configuration error.

====================================================
PART 4 — Configuration Cache
====================================================

Configuration may be cached.

If cached:

Reload automatically whenever the admin updates level.config.

Do not require a backend restart.

====================================================
PART 5 — Admin Panel
====================================================

Admin Compensation page must display:

Level 1 → 1%

Level 2 → 1%

Level 3 → 1%

Level 4 → 1%

Level 5 → 1%

Saving from the admin panel must update system_settings.

Future edits should immediately affect new payouts.

Historical payouts must remain unchanged.

====================================================
PART 6 — Startup Log
====================================================

On backend startup log:

Level Income Configuration Loaded

Levels: 5

Rates:

L1 → 1%

L2 → 1%

L3 → 1%

L4 → 1%

L5 → 1%

====================================================
PART 7 — Regression Tests
====================================================

Verify:

✓ Existing users still receive exactly the same payouts.

✓ A $100 investment pays:

Level 1 → $1

Level 2 → $1

Level 3 → $1

Level 4 → $1

Level 5 → $1

✓ No historical ledger entries change.

✓ No wallet balances change.

✓ Existing withdrawal, treasury, reconciliation, ROI, binary, and salary modules remain unaffected.

====================================================
Acceptance Criteria
====================================================

After completion:

There is exactly ONE source of truth for level income percentages.

Backend payout engine reads only system_settings.level.config.

Configuration matches the official PrimeWave compensation plan:

1%
1%
1%
1%
1%

TypeScript passes.

No regression in investment processing.

No financial records are modified.

No migration of historical data is required.
