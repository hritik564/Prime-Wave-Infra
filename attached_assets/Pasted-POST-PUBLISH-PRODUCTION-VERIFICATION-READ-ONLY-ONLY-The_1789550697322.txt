9. PROCESSOR CODE VERIFICATION
==================================================

Verify that the PUBLISHED runtime contains the latest processor fixes.

Specifically confirm:

A. Distributed nonce lock:
- PostgreSQL advisory lock is still used.
- Prisma no longer attempts to deserialize the PostgreSQL void result.
- The lock is transaction-scoped.

B. Signing lifecycle:
- SIGNED is recorded only after actual cryptographic signing succeeds.
- signedAt is not set merely because the processor entered the sign/broadcast phase.

C. Broadcast lifecycle:
- BROADCASTING occurs immediately before RPC submission.
- txHash is persisted only after eth_sendRawTransaction successfully returns a valid hash.
- broadcastAt is persisted only after a valid transaction hash is received.

D. Failure classification:
- pre-signing failure → PENDING
- genuine signing/broadcast ambiguity → BROADCAST_UNKNOWN
- no automatic refund on processor failure

E. Retry safety:
- no automatic retry of ambiguous broadcasts
- raw transaction submission is not blindly retried after an ambiguous network error

Report PASS/FAIL for each.
