# Sprint 26 — Financial Transparency Center

## Objective

Prime Wave's financial engines are now considered stable.

Sprint 26 is NOT a financial engine sprint.

Its purpose is to make every financial process transparent to users.

Every user should immediately understand:

• What income they currently qualify for.
• Why they qualify (or why they don't).
• When each income will be credited.
• How much income is currently expected.
• What is pending.
• What action (if any) they need to take.

This sprint is READ ONLY.

No financial calculations may be changed.

No financial engine may be modified.

----------------------------------------------------------------

## CORE ARCHITECTURE RULE

The Financial Transparency Center must NEVER implement business logic.

It must NEVER calculate:

• ROI
• Binary Matching
• Salary
• Level Income
• Orbit

Instead it must consume existing engine outputs, scheduler metadata and database records.

If any information is missing, expose it through lightweight READ ONLY APIs.

Do not duplicate financial rules.

Do not duplicate engine calculations.

----------------------------------------------------------------

## Build Financial Transparency API

Create a dedicated read-only aggregation service.

Example:

GET /api/financial-transparency

(or an equivalent endpoint)

This endpoint should aggregate data from existing services only.

It must never execute any financial engine.

It must never modify database state.
