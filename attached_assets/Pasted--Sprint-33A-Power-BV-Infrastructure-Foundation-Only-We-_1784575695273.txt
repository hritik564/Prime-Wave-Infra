# Sprint 33A – Power BV Infrastructure (Foundation Only)

We are implementing a new first-class feature called "Power BV (Power Leg)".

⚠️ IMPORTANT:
This sprint is FOUNDATION ONLY.

Do NOT modify any bonus engine yet.

Specifically:

- Do NOT change Binary Matching.
- Do NOT change Binary Orbit.
- Do NOT change Salary Qualification.
- Do NOT change Salary Scheduler.
- Do NOT change Level Income.
- Do NOT change investment propagation.
- Do NOT change BV calculations.

The platform must behave EXACTLY as it does today after deployment.

--------------------------------------------------
OBJECTIVE
--------------------------------------------------

Create the complete infrastructure for Power BV so future sprints can safely integrate it.

Power BV is NOT seeded business.

Power BV is an administrator-controlled business volume that belongs ONLY to the assigned member.

Rules:

• Never propagates upward.
• Never creates investment records.
• Never creates BV history entries.
• Never creates level income.
• Never creates sponsor business.
• Never affects existing calculations in this sprint.

It is simply stored, managed and audited.

--------------------------------------------------
DATABASE CHANGES
--------------------------------------------------

Add two new columns to User:

powerLeftBV
Decimal(18,8)
Default = 0

powerRightBV
Decimal(18,8)
Default = 0

Do NOT modify:

- leftBV
- rightBV

--------------------------------------------------
NEW LEDGER TABLE
--------------------------------------------------

Create:

PowerBvLedger

Fields:

- id
- userId
- side (LEFT / RIGHT)
- operation (ADD / REMOVE)
- bv
- balanceBefore
- balanceAfter
- adminId
- reason
- metadata (optional JSON)
- createdAt

Requirements:

- Immutable
- Never update rows
- Never delete rows
- Every Power BV change must create one ledger row

--------------------------------------------------
SERVICE LAYER
--------------------------------------------------

Create:

src/binary/power-bv.service.ts

Functions:

- addPowerBV()
- removePowerBV()
- getPowerSummary()
- getPowerLedger()

Requirements:

- Prisma interactive transactions
- Lock user row before update
- Prevent negative balances
- Validate inputs
- Atomic update + ledger write

--------------------------------------------------
VALIDATION
--------------------------------------------------

Create:

power-bv.schema.ts

Validation:

- side = LEFT | RIGHT
- BV > 0
- configurable maximum per operation
- reason required
- minimum reason length

--------------------------------------------------
ADMIN API
--------------------------------------------------

Create:

POST /api/admin/power-bv/:userId/add

POST /api/admin/power-bv/:userId/remove

GET /api/admin/power-bv/:userId

GET /api/admin/power-bv/:userId/ledger

Permissions:

- SUPER_ADMIN
- FINANCE_ADMIN

Read endpoints available to existing admin roles.

--------------------------------------------------
ADMIN LOGGING
--------------------------------------------------

Every add/remove operation must also create an AdminLog entry.

Actions:

POWER_BV_ADD

POWER_BV_REMOVE

Include:

- Admin
- User
- Side
- Amount
- Reason

--------------------------------------------------
ADMIN UI
--------------------------------------------------

Create a new "Power BV" tab inside the existing member drawer.

Display:

Organic Left BV

Power Left BV

Organic Right BV

Power Right BV

Effective Left BV (Organic + Power)

Effective Right BV (Organic + Power)

Current Power BV balances

Provide:

- Add Power BV
- Remove Power BV
- Reason
- Confirmation dialog

Ledger Table:

- Date
- Admin
- Side
- Operation
- Amount
- Balance Before
- Balance After
- Reason

Provide CSV export.

IMPORTANT:

Effective BV shown in the UI is DISPLAY ONLY.

No backend calculations should use it yet.
