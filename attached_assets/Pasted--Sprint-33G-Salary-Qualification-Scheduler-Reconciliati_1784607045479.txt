# Sprint 33G – Salary Qualification Scheduler & Reconciliation

Sprint 33F has been approved.

This sprint implements the operational layer of the Salary Engine.

⚠️ IMPORTANT

This sprint DOES NOT change any qualification rules.

It simply executes the Qualification Engine built in Sprint 33F in a safe, scalable and fault-tolerant manner.

Do NOT modify:

- Qualification logic
- Effective business calculation
- Salary payouts
- SalaryIncome generation
- Member UI
- Admin UI

--------------------------------------------------
OBJECTIVE
--------------------------------------------------

Build the automation layer for the Salary Engine.

The scheduler must:

• Execute qualification automatically

• Support incremental qualification

• Support full reconciliation

• Isolate failures

• Never create duplicate achievements

• Be completely idempotent

--------------------------------------------------
NEW SERVICE
--------------------------------------------------

Create:

src/salary/salary-scheduler.service.ts

Responsibilities:

• Run qualification for one user

• Run qualification for all users

• Incremental processing

• Full reconciliation

• Logging

• Metrics

--------------------------------------------------
JOB TYPES
--------------------------------------------------

Implement four internal jobs.

--------------------------------------------------
JOB 1

Incremental Qualification
--------------------------------------------------

Runs whenever:

Investment Created

Investment Cancelled

Investment Refunded

Power BV Added

Power BV Removed

Instead of qualifying every member,

qualify ONLY affected users.

Typical flow:

Business Event

↓

SalaryBusinessSummary updated

↓

Qualification Scheduler

↓

evaluateUser(userId)

--------------------------------------------------
JOB 2

Nightly Qualification
--------------------------------------------------

Once daily.

Iterate every ACTIVE user.

For each user:

Run Salary Qualification.

Failures must NOT stop the batch.

Continue processing.

Produce summary metrics.

--------------------------------------------------
JOB 3

Full Reconciliation
--------------------------------------------------

Administrative job.

Purpose:

Rebuild qualification state from existing SalaryBusinessSummary.

For every ACTIVE user:

Run qualification.

Do NOT touch SalaryBusinessSummary.

Do NOT touch SalaryBusinessEvent.

Only create missing SalaryAchievement rows.

Update:

lastReconciledAt

on successful completion.

--------------------------------------------------
JOB 4

Single User Rebuild
--------------------------------------------------

Internal helper.

Input:

userId

Execute:

Qualification

Return:

Summary object.

Useful for:

Future Admin tools

Support debugging

Recovery

--------------------------------------------------
FAILURE ISOLATION
--------------------------------------------------

Every user executes independently.

Example:

User 100 fails.

↓

Log error.

↓

Continue with User 101.

Never abort an entire nightly batch because one user failed.

--------------------------------------------------
CONCURRENCY
--------------------------------------------------

Implement configurable batching.

Example:

100 users

↓

10 workers

↓

10 users per worker

Avoid one gigantic transaction.

Each user:

Own transaction.

--------------------------------------------------

Collect:

usersProcessed

usersSucceeded

usersFailed

newAchievementsCreated

duplicatesSkipped

durationMs

Return metrics object.

--------------------------------------------------
LAST RECONCILED
--------------------------------------------------

Only the reconciliation job updates:

SalaryBusinessSummary.lastReconciledAt

Normal qualification runs MUST NOT update it.

--------------------------------------------------
IDEMPOTENCY
--------------------------------------------------

Running:

Nightly Qualification

twice

must produce:

Zero duplicate achievements.

Reconciliation

twice

must produce:

Zero duplicate achievements.

Events:

--------------------------------------------------

Optimise for scalability.

• Fetch users in batches.

• Avoid loading unnecessary relations.

• Use existing indexes.

• No N+1 queries where avoidable.

• Keep memory usage bounded.
