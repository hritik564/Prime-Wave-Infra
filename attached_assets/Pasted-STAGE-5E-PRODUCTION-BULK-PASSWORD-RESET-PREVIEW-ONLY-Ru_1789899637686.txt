STAGE 5E — PRODUCTION BULK PASSWORD RESET PREVIEW ONLY

Run the production bulk password reset PREVIEW endpoint only.

This is a READ-ONLY planning operation.

CRITICAL:
- DO NOT execute the bulk reset.
- DO NOT call /api/admin/security/bulk-password-reset/execute.
- DO NOT generate temporary passwords.
- DO NOT create a credential artifact.
- DO NOT update passwordHash.
- DO NOT update passwordResetRequired.
- DO NOT update authVersion.
- DO NOT update passwordChangedAt.
- DO NOT modify users, admins, wallets, investments, deposits, withdrawals, income, BV, referrals, or any financial/business data.
- Do not create a bulk_password_reset_runs record unless the preview endpoint itself is explicitly documented as read-only. Prefer no database mutation.
- Do not expose secrets or password hashes.

Use the authenticated SUPER_ADMIN context for the existing PrimeWave admin account.

Call:

POST /api/admin/security/bulk-password-reset/preview

The preview must target ALL NORMAL USERS, meaning the Prisma User model only, across every user status.

Admins must be excluded completely.

Return the complete preview information without exposing any credentials:

1. Total eligible normal users
2. Counts by user status:
   - ACTIVE
   - INACTIVE
   - BLOCKED
   - SUSPENDED
3. Seeded sp###### users
4. Non-seeded users
5. Total admins detected
6. Admins excluded from the operation
7. Users with unexpected authVersion != 0
8. Users with passwordResetRequired = true
9. Any existing bulk reset run
10. Whether the exact confirmation phrase would be required for execution
11. The expected user count that would have to be supplied for execution

The expected eligible count should be 6,640 based on Stage 5D, unless live production data has legitimately changed since that verification.

IMPORTANT:
Do not proceed from preview to execute.
Do not ask the endpoint to execute automatically.
Stop immediately after obtaining the preview.

Final line must explicitly say:

BULK PASSWORD RESET EXECUTION: NOT EXECUTED
