Confirmed behavior:

- File selection works.
- Local preview works.
- POST /api/admin/company-wallets/qr-upload-url returns HTTP 200.

  "Load failed"

- The uploaded test PNG is valid:
  - 235 × 235
  - valid PNG
  - 4,713 bytes
  - QR successfully decodes
- The QR payload was:
  0x543780…658BDb

  0x543780…658BDb

- The current active production BEP20 wallet remains:
  0x1f4d…B991

OBJECTIVE:

Fix the QR upload workflow so Super Admins can reliably upload PNG QR images from the production Admin Settings → Deposit Wallet Management interface.

PREFERRED ARCHITECTURE:

Avoid relying on a browser cross-origin PUT directly to the App Storage/GCS presigned URL if the existing App Storage integration provides a safe server-side upload mechanism.

Prefer:

Browser
→ authenticated application API
→ server-side App Storage upload
→ stored object
→ QR validation
→ wallet profile create/update

If the existing project already has a secure server-side App Storage upload helper, reuse it rather than creating a second storage abstraction.

If a server-side upload is NOT supported by the existing App Storage integration, then investigate and correctly configure the existing presigned-upload flow instead. Do not weaken security or use an insecure proxy.

UPLOAD VALIDATION:

After the upload succeeds, the existing QR validation must still execute.

The flow should verify:

1. The uploaded object exists.
2. The object can be read by the backend.
3. It is a valid PNG.
4. The QR can be decoded.
5. The decoded payload is a valid BEP20 address.
6. The decoded address exactly matches the address being saved.
7. Only then should the wallet profile be created or updated.

ERROR HANDLING:

Replace the current generic behavior where a browser "Load failed" becomes:

"QR validation failed."

The UI should distinguish upload failures from QR validation failures.

For example:

- Upload failure:
  "QR upload failed. Please try again."
- Invalid PNG:
  "The selected file is not a valid PNG."
- QR cannot be decoded:
  "Could not read a QR code from this image."
- QR/address mismatch:
  "QR address does not match the wallet address."
- Successful validation:
  Continue to the normal save flow.
