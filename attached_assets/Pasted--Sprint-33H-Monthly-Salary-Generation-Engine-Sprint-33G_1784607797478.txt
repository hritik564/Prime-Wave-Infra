# Sprint 33H – Monthly Salary Generation Engine

Sprint 33G has been approved.

This sprint implements the Monthly Salary Generation Engine.

The business rule has been finalized:

✅ Monthly Snapshot Model

A member earns salary based on the highest qualified rank at the moment the monthly salary job runs.

Once generated, that month's salary is permanently locked.

Future promotions do NOT change historical months.

--------------------------------------------------
OBJECTIVE
--------------------------------------------------

Implement the Monthly Salary Generation Engine.

The engine must:

• Generate one SalaryIncome record per eligible member per month.

• Use snapshot qualification.

• Never modify previously generated months.

• Be completely idempotent.

• Be fully transactional.

--------------------------------------------------
NEW SERVICE
--------------------------------------------------

Create:

src/salary/salary-income.service.ts

Responsibilities:

• Determine highest qualified rank

• Generate monthly salary

• Prevent duplicate generation

• Support one user

• Support batch generation

--------------------------------------------------
MONTHLY SNAPSHOT RULE
--------------------------------------------------

When the monthly job runs:

Determine:

Highest SalaryAchievement currently held.

Generate ONE SalaryIncome record.

Example:

July 1

Highest Rank

Ruby

↓

Generate

July Salary

↓

Locked forever.

Example:

July 15

User reaches Emerald.

↓

July salary remains Ruby.

↓

Emerald applies from August generation.

Historical months never change.

--------------------------------------------------
HIGHEST RANK
--------------------------------------------------

Determine the highest qualified rank using:

SalaryAchievement

JOIN

SalaryRankConfig

ordered by rank order / requiredBusiness descending.

Generate salary only for the highest rank.

Never generate multiple salaries for one month.

--------------------------------------------------
SALARY AMOUNT
--------------------------------------------------

Use:

SalaryRankConfig.monthlySalary

(or the existing configured salary amount field)

No hardcoded salary values.

Configuration drives everything.

--------------------------------------------------

reference

Use the existing SalaryIncome model if present.

If required fields are missing, extend the model minimally.

Do NOT redesign SalaryIncome.
