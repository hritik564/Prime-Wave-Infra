SPRINT 27E — DATABASE CONNECTION POOL AUDIT & DEPOSIT RESILIENCE

We have confirmed a production issue.

A legitimate deposit reached CONFIRMED but failed to complete because Prisma threw:

Timed out fetching a new connection from the connection pool.
Connection limit: 5
Pool timeout: 10s

The transaction later succeeded after Re-Validate.

This indicates an infrastructure/database bottleneck rather than a blockchain issue.

==========================================================
OBJECTIVE
==========================================================

Perform a complete audit of database connection usage during deposit verification.

Do not guess.

Trace the exact lifecycle of a successful deposit.

==========================================================
RESILIENCE IMPROVEMENTS
==========================================================

If Prisma temporarily cannot obtain a connection:

DO NOT permanently fail the verification.

Instead:

Retry the database operation using exponential backoff.

Example:

250ms

500ms

1s

2s

Maximum 5 retries.

If retries still fail:

Return the verification to VERIFYING.

Set nextCheckAt = now + 30 seconds.

Allow the worker to retry naturally.

Never lose a valid blockchain verification because of a temporary DB connection shortage.
